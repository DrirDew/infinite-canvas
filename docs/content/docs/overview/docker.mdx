# Docker Deployment

## Use the published image

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
docker compose up -d
```

Open `http://localhost:3000`.

## Build locally

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## Documentation image

The documentation in `docs/` is a separate Next.js standalone application with server capabilities.

```bash
cd docs
docker compose up -d
```

To build it from the current source:

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

The main application container serves the static frontend and proxies `/api` to the company provider service. Canvases, My Assets, generation history, and personal API keys are stored in the browser by default. Company Tencent Cloud VOD credentials stay in server environment variables and are never sent to the browser.

## Optional access protection

Copy `.env.example` to `.env` in the repository root and set `AUTH_PASSWORD`. Docker Compose reads that file automatically.

```env
AUTH_USER=admin
AUTH_PASSWORD=your-password
TENCENT_VOD_SECRET_ID=
TENCENT_VOD_SECRET_KEY=
TENCENT_VOD_SUB_APP_ID=
```

| Variable | Description |
| --- | --- |
| `AUTH_USER` | Username, default `admin` |
| `AUTH_PASSWORD` | Password; empty disables auth |
| `TENCENT_VOD_SECRET_ID` | Company Tencent Cloud SecretId; empty hides the company provider |
| `TENCENT_VOD_SECRET_KEY` | Company Tencent Cloud SecretKey; never sent to the browser |
| `TENCENT_VOD_SUB_APP_ID` | Company VOD application ID |

```bash
docker compose -f docker-compose.local.yml up -d --build
```

Do not reuse another app's `.env.production`. After changing `.env`, run `docker compose -f docker-compose.local.yml up -d` so the container picks up the new password and company credentials.

Do not commit real passwords or Tencent Cloud secrets. Company generation goes through `/api` and stays behind Basic Auth. The `/tencent-vod` proxy stays outside Basic Auth because personal providers still use Tencent Cloud signature headers.

## Optional analytics

No analytics are enabled by default. A deployment can enable GA4, Baidu Analytics, or both at runtime:

| Variable | Description |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 measurement ID (`G-XXXX`) |
| `ANALYTICS_BAIDU_ID` | Baidu site ID, the hash after `hm.js?` |

```yaml
services:
  app:
    image: ghcr.io/basketikun/infinite-canvas:latest
    ports:
      - "3000:3000"
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

SPA route changes automatically report page views to enabled providers. Only configure analytics IDs on sites you control, and do not commit them to the repository.
