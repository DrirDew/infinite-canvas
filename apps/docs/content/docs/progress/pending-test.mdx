# Pending Tests

The current release needs manual verification in these areas:

- Core document state: `apps/examples` should run using only `@infinite-canvas/core`; its two canvases must keep document snapshots, selection, undo, and redo state isolated, and each snapshot node count should follow additions and removals. In the official Web canvas, loading, saving, adding, deleting, pasting, media replacement, AI streaming generation, retry, batch-image updates, dragging, resizing, grouping, connections, Agent edits, and plugin node edits should keep their existing behavior, while undo and redo restore only nodes and connections rather than chat, background, or image-info settings.
- Core viewport and box selection: the two Examples canvases must keep container size, viewport, rectangle selection, and minimap bounds isolated and update them after resizing; their focus and reset buttons must affect only the current instance. The official Web canvas should preserve project viewport loading and saving, initial centering, panning, wheel and centered-control zoom, reset, animated node focus, minimap navigation, screen-to-canvas coordinates, normal box selection, and Shift/Cmd additive box selection; panning, wheel zoom, or minimap navigation during focus animation must take control without viewport rebound.
- Core node interaction: nodes in the two Examples canvases must drag and resize independently through the Core interaction entry points and use Core's configurable minimum size; the official Web canvas should preserve its existing 220×160 minimum, single, multi-node, and group dragging, child movement with groups, group drop snapping, leaving groups, four-corner resizing, image and video ratio locking, undo, and redo, with each continuous drag or resize producing one history entry. Pointer cancellation, window blur, or control unmount during resize must restore the original bounds, add no history entry, and leave no stuck resizing state.
- Core behavior options: a standalone consumer should be able to customize history capacity, drag threshold, group padding, connection handle radius, and nearby-node padding per canvas instance without changing the stable command object or affecting another instance; omitted options must preserve the official Web behavior.
- Core render defaults: `canvasDefaults` should expose the default resize minimums and handle size, connection port hit size/offset/indicator, connection stroke hit width, minimap dimensions, world padding, minimum visible sizes, and keyboard step used by the corresponding geometry and React components.
- Core grouping policy: a standalone consumer should be able to reject specific node/group combinations through `canGroupNode`; rejected groups must not appear as drop targets or become the node's final `groupId`, while another instance using default behavior remains unaffected.
- Core grouping policy integrity: `canGroupNode` must also govern direct node additions, updates, resize previews, clipboard paste, and `getCanvasDocumentIssues`; rejected ownership should be removed by commands and reported as `rejected-group` by validation.
- Core state callbacks: `onSelectionChange` and `onInteractionChange` should receive the latest state after command-driven selection, drag, resize, connection start/end/cancel, document replacement, and cleanup caused by node deletion, without making the command object unstable.
- Core no-op notifications: selecting the same node/connection set or writing an equal viewport must not fire duplicate state/input callbacks, while `setDocument` must still publish its explicit selection and interaction reset.
- Core document replacement: `setDocument` should publish the exact supplied snapshot through `onDocumentChange`, clear selection, interaction, undo, and redo state, and affect only its own canvas instance.
- Core selection integrity: selecting missing node or connection IDs, including missing IDs in additive marquee input, must silently discard those IDs and keep the selection limited to the current document.
- Core readonly selection: TypeScript consumers should receive `ReadonlySet<string>` from canvas results, selection callbacks, `getSelection`, and marquee selection results; existing Web panels and Agent adapters should continue reading and cloning selections without direct mutation.
- Core readonly inputs: selectors, geometry functions, connection/minimap renderers, and `addNodes`/`addConnections` should accept readonly arrays from immutable stores or `as const` snapshots without consumer-side cloning.
- Core preview lifecycle: `cancelPreview` must restore the pre-preview document without adding history or firing document persistence; undo/redo during an uncommitted resize or custom preview must cancel that preview first, while a transaction started after a preview commits both edits in order.
- Core document integrity: add-node commands must ignore empty or duplicate IDs; add-connection commands must ignore duplicate IDs, missing endpoints, self-links, group links, rejected policy results, and resolver outputs that point outside the requested node pair, without adding empty history entries.
- Core node update integrity: updating a node to an empty or duplicate ID must be ignored; renaming a group must update child ownership and connected endpoints, while removing its group role or changing a connected node into a rejected type must clear invalid ownership and connections in the same history entry.
- Core no-op updates: patches that keep all engine fields equal, recreate only an equal position object, or request a rejected group that normalizes back to the current value must preserve document identity, publish no snapshot, and add no undo entry.
- Core document validation: `getCanvasDocumentIssues` should report empty/duplicate IDs, invalid top-level group ownership, missing/self/group connections, and injected-policy rejection for external documents without mutating the supplied object.
- Core viewport options: standalone canvases should independently respect custom minimum/maximum zoom, focus coverage, focus maximum zoom, focus duration, and grid size; wheel zoom and centered controls must use the same configured range, while omitted options preserve the official Web defaults.
- Core viewport callback semantics: `onViewportInput` should fire for panning, wheel zoom, and minimap navigation routed through the returned `onViewportChange`, but not for programmatic reset, focus, or `setZoom`; the `useCanvas` state callback should continue observing every committed viewport change.
- Core package entry points: a standalone project should be able to import the full API from `@infinite-canvas/core`, pure document/geometry APIs from `@infinite-canvas/core/headless`, and Hooks/components from `@infinite-canvas/core/react`; the headless entry must not evaluate React modules or require TypeScript's DOM lib for coordinate and shortcut declarations.
- Core native ESM: after publishing, native Node ESM should import `@infinite-canvas/core/headless` without extension-resolution flags, while Vite/React consumers continue resolving the root and React entries with source maps and declaration maps available.
- Core package metadata: the published package should expose its repository, README, issue tracker, keywords, and MIT license, require React 18+ without an unused `react-dom` peer, and include only `dist`, `README.md`, and `LICENSE` as declared public artifacts.
- Core editor composition: a standalone React consumer should be able to create the same isolated state and interaction API through `useCanvasEditor({ canvas, interactions })`, with nested callbacks and options reaching the corresponding lower-level hooks.
- Core pointer orchestration: Examples and the official Web canvas should preserve click selection, Shift/Cmd toggling, marquee selection, node drag completion, connection preview and drop, cancellation on pointer cancel or window blur, and opening the existing business panel or blank-drop creation menu after Core reports the result.
- Core pointer API: mouse, touch, and pen pointer-down events should enter the same canvas selection, node drag, and connection-start paths through the public `PointerDown` handlers; connection handles must not also start a node drag.
- Core multi-pointer ownership: while one pointer pans, marquee-selects, drags a node, creates a connection, resizes, or navigates the minimap, move/up/cancel events and new starts from another pointer must not alter or finish that operation; a second pointer must not start panning during marquee, node drag, or connection creation, and a second resize-handle press or unrelated pointer release must leave the original resize active.
- Core multi-instance input: Space/Control tool inversion must affect only the focused canvas, clicking a non-editable canvas target should focus that instance, editable controls must retain native Space behavior, and ending or unmounting one pan must not clear another instance's grabbing cursor.
- Core shared window events: mounting multiple canvases should keep drag, connection, resize, blur cleanup, and focus-animation cancellation isolated while Core registers only one native listener per global event type and removes it after the final subscriber unmounts.
- Core pointer buttons: right-clicking a node, resize handle, or connection handle must not start dragging, resizing, or connection creation; middle-button canvas panning and primary-button editing must keep working.
- Core connection interaction: the two Examples canvases must create, select, and delete connections independently by dragging from node handles and clicking connection paths, with generic source/target direction. The official Web canvas should preserve its injected Config direction and invalid-pair rules, source- and target-handle starts, node and handle hit testing, duplicate prevention, connection selection, context menus and deletion, create-and-connect on blank space, undo, and redo.
- Core clipboard and shortcuts: copied content must stay isolated between the two Examples canvases; the official Web canvas should preserve multi-node and internal-connection copying, centered paste, group remapping, one undo entry per paste, select all, delete, Escape, macOS and Windows/Linux undo and redo shortcuts, and system clipboard image and text imports.
- Core clipboard integrity: pasted node and connection IDs generated by the host must pass the same empty, duplicate, group, endpoint, and connection-policy checks as normal add commands; a paste with no accepted nodes must return `null`, preserve selection and history, and never connect rejected IDs to existing nodes.
- Core basic rendering: Examples should display the dedicated unknown-node placeholder; Examples and the official Web canvas should preserve node positioning, four-corner resizing, source and target handles, unknown-plugin placeholders, normal and active connection paths (including nodes at negative coordinates or beyond 10000 canvas units), selection and related highlights, context-menu hit areas, scale-independent selection-box strokes, node thumbnail colors, minimap viewport rectangles, and click-drag minimap navigation.
- Core custom background: `InfiniteCanvas` should pass the latest viewport, theme, mode, and grid size to `renderBackground`, allow `backgroundStyle` overrides, render custom content in blank mode, and keep the managed background layer pointer-transparent during panning and selection.
- Core render integration: `contentClassName` and `contentStyle` should customize the transformed world layer without changing viewport positioning, and stable data attributes should identify the canvas root, background, content, connections, selection, minimap viewport, and unknown-node placeholder.
- Core node controls: standalone consumers should be able to customize resize-handle size and content plus connection-handle hit size, offset, indicator size, and source/target content without replacing Core pointer behavior; omitted props must preserve current Web controls.
- Core connection paths: a standalone consumer should be able to inject one `resolvePath` function for both persisted connections and the active connection preview, enabling straight, orthogonal, or custom routing without replacing the connection layer.
- Core connection styling: a standalone consumer should be able to style each normal or active connection through `resolveStyle`, customize the active preview through `previewStyle`, and adjust the transparent selection target through `hitStrokeWidth`, while click and context-menu callbacks keep working.
- Core connection container: `CanvasConnectionLayer` should apply custom SVG `className` and `style` while preserving overflow, hit paths, selection, context menus, and custom path/style resolvers.
- Core selection rendering: a standalone consumer should be able to customize the selection-box container and SVG rectangle through `className`, `style`, and `rectProps`, while omitted props preserve scale-independent default strokes.
- Core minimap layout: standalone canvases should independently respect custom `worldPadding`, minimum node size, minimum viewport size, container class, dimensions, and styles without changing navigation coordinates in another instance.
- Core minimap rendering: `nodeStyle`, `renderNode`, and `viewportStyle` should customize node shapes/content and the viewport indicator while Core continues positioning them and handling click-drag navigation.
- Core minimap input isolation: clicking or dragging empty minimap space must navigate only the viewport without starting canvas marquee selection, and wheel input over the minimap must not zoom the main canvas.
- Core minimap keyboard navigation: the minimap should expose a configurable accessible label and tab stop; Arrow keys must move only its own viewport by `keyboardStep`, prevent page scrolling, and leave another canvas instance unchanged.
- Core empty minimap: custom `worldPadding` should affect the empty-document viewport rectangle and continue using the same padding semantics after the first node is added.
- Core node roles: official image, text, config, video, and audio nodes must preserve their existing rendering and behavior after their type enum moves to Web; group nodes created by the toolbar or Agent must keep group dragging, child movement, snapping, clipboard remapping, and connection blocking through `role: "group"` and top-level `groupId`, without writing grouping state into business metadata.
- Core Agent adapter: Agent connection operations must reject group and invalid Config pairs; deleting a group through Agent operations must remove related connections and clear child `groupId` values while remaining one Core transaction.
- Core theme source: the canvas, image and video workbenches, Agent canvas previews, toolbars, popovers, menus, nodes, minimap, and plugin panels should preserve their existing light and dark colors after Web removes its duplicated theme definition.
- Core custom themes: a standalone TypeScript consumer should be able to construct a `CanvasTheme` with arbitrary CSS color strings or extend either default theme without casts, and all base renderers should consume it consistently.
- Plugin registry: the Sticky Note example must no longer appear in official plugins or be included in the published plugin bundle.
- Monorepo migration: installing once from the repository root should create all Bun workspace links; `bun run dev`, documentation development, Canvas Agent development, official plugin builds, Docker, Vercel, and GitHub Pages should continue to use the relocated `apps/web`, `apps/docs`, `packages/canvas-agent`, `packages/plugin-sdk`, and `plugins/user` paths.
- Canvas navigation: the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should pan from either the background or a node. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. Holding Control or Space should temporarily invert the active tool without changing the toolbar mode: Select becomes Move, and Move becomes range selection. After clicking any canvas-page button, pressing Space should only invert the tool and must not trigger that button again. Middle-button panning and additive node selection with Shift/Cmd should continue to work, while Space remains available inside text inputs and editable content.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration.
- Canvas side panel: clicking an element row should smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one image node with N expandable slots and one incoming connection; each empty slot should independently show generating or failure while requests are running, every slot with image content should always display that image, and the first successful image should appear as the primary image immediately. The collapsed state should use a compact stack with at most three closely spaced backplates and a clearly legible count control; clicking the control should hide the floating toolbar and expand the slots upward and to the right. Every completed secondary image should keep a clearly legible primary-image action visible in both themes, and clicking the empty canvas should collapse the group.
- Multi-image primary selection: choosing another primary image should preserve the node center and current maximum edge while adapting to the new image ratio; free-resize nodes should keep their exact dimensions, and the viewport zoom indicator must not change.
- Failed multi-image slots: every failed slot, including the current primary slot, should expose retry and delete actions. Retry should update only that slot without replacing an existing successful primary image; delete should remove only that failed slot and update the displayed count.
- Multi-image resize: starting a resize while child images are expanded should collapse the group once, then resize the root node normally without triggering nested React updates or an application error.
- Multi-image alternatives: expanded images should use up to four columns so larger batches stay compact; every completed image, including the primary image, should provide an independent download action, while alternatives should also keep clearly legible create-copy and set-primary actions in both themes. Create-copy should add an independent image node to the right of the group, select it, and leave the original image group unchanged.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.
- Agent header tabs in English and Chinese at different panel widths; labels should collapse to icons and counts before either edge is clipped.
- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Agent inline references: type `/` to select an enabled Skill or `@` to select a canvas asset at the caret; tokens should remain aligned with text, support keyboard navigation and hover previews, and preserve their positions after sending or refreshing.
- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets without relying on browser IndexedDB or text matching.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- Settings import/export, Volcengine Ark protocol handling, and WebDAV-related configuration.
- Local storage settings: the Settings page should provide a Local storage tab that reads only the `infinite-canvas` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.
